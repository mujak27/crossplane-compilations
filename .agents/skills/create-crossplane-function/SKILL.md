# Create Crossplane Function

Read [`docs/adding-a-function.md`](../../../docs/adding-a-function.md) before
acting; it is the authoritative workflow. Use
[`function-template/README.md`](../../../function-template/README.md) for template
mechanics and its manual customization checklist.

Identify whether the user asked for planning, implementation, or validation, and
stay within that scope. Resolve the domain decisions, use the template and
generation pipeline when implementing, run the guide's acceptance checks, and
report results and blockers.

If the user wants issue- or ticket-based coordination and `plan-to-tickets` is
available, load it through the harness's skill mechanism and follow its
requirements. Otherwise use the direct workflow above; optional coordination is
not required.

Obtain explicit user approval before publishing issues or tickets, dispatching
implementation, building or publishing packages, deploying, or taking other
external actions. Skill invocation is not that approval.
